# 语义检索：返回的片段要显示定义那一行

_2026-11-26 · 由 Opus 5.5 编写，GLM 5.3 FlashX 实施，Opus 复审_

## 问题

按函数名搜索时，检索排第一的块是对的，但模型看到的片段里没有函数定义。用线上 `1.1.1-3749096b` 二进制在两个 Python 仓库的 285 个函数上逐个按名字查：

| 结果 | 数量 |
|---|---:|
| 目标块排第一 | 265 |
| 返回片段里没有定义那一行 | 79 |
| 其中：函数签名被并进上一个函数的块尾，块到签名就结束 | 48 |
| 其中：一块里有几个小函数，目标不在片段的前 10 行 | 31 |

原因一（切块）：函数超过 `desired_chunk_bytes`（750）时，`split_node` 把 `def name(...) :` 这几个小子节点单独成一块，函数体另起一块；随后 `merge_adjacent` 把签名这一小块并到上一个函数的末尾。函数体那块里没有函数名。

原因二（预览）：片段总是从块的第一行开始，取 `max_snippet_lines`（产品里是 10 行）。块里第三个函数的定义看不到。

评测看不出来：`repoqa-query` 把片段正文关掉，只按行号范围判分。

## 测试先行

每一步先写失败的测试，看到它失败，再改实现。测试名写行为。

### 1. 切块：签名跟着函数体走

文件：`crates/semble-core/src/chunk/tree_sitter.rs`

先写测试（在该文件的 `tests` 模块里，用 `chunk_source(..., Some("python"), desired)`，`desired` 取 120 左右，让第二个函数必须被拆开）：

- `a_split_function_keeps_its_signature_with_the_start_of_its_body`：源码是一个很短的函数 `def small(): return 1`，后面接一个多行签名、函数体十几行的大函数 `def large(\n    first,\n    second,\n):\n    alpha = first\n ...`。断言：包含 `def large(` 的那一块，同时包含函数体第一条语句 `alpha = first`。
- `a_decorated_split_function_keeps_decorator_signature_and_body_start_together`：大函数前加 `@cached`。断言：包含 `@cached` 的块同时包含 `def large(` 和 `alpha = first`。
- 保留现有三个测试不变。

实现：给 `split_node` 增加参数 `lead: Option<usize>`，表示“本节点产出的第一块要从这个字节开始”。调用处 `split_node(tree.root_node(), desired, 0, None)`。参考写法：

```rust
fn split_node(
    node: Node<'_>,
    desired: usize,
    depth: usize,
    lead: Option<usize>,
) -> Vec<ChunkBoundary> {
    if node.child_count() == 0
        || depth > MAX_DEPTH
        || node.end_byte().saturating_sub(node.start_byte()) < MIN_CHUNK_BYTES
    {
        return vec![ChunkBoundary {
            start: lead.unwrap_or(node.start_byte()),
            end: node.end_byte(),
        }];
    }
    // A definition's decorators and signature are too small to stand alone; split
    // off, they end up at the tail of the previous definition's chunk.
    let body = node
        .child_by_field_name("body")
        .or_else(|| node.child_by_field_name("definition"));
    let mut cursor = node.walk();
    let children = node.children(&mut cursor).collect::<Vec<_>>();
    let mut output = Vec::new();
    let mut lead = lead;
    let mut index = 0;
    while index < children.len() {
        let child = children[index];
        index += 1;
        let start = lead.unwrap_or(child.start_byte());
        if child.end_byte().saturating_sub(start) > desired {
            output.extend(split_node(child, desired, depth + 1, lead.take()));
            continue;
        }
        lead = None;
        let mut end = child.end_byte();
        while index < children.len() && children[index].end_byte().saturating_sub(start) <= desired
        {
            end = children[index].end_byte();
            index += 1;
        }
        if body.is_some_and(|body| children.get(index) == Some(&body)) {
            lead = Some(start);
            continue;
        }
        output.push(ChunkBoundary { start, end });
    }
    output
}
```

要点：签名组在函数体前停下、且下一个子节点就是 `body`/`definition` 时，不单独输出，把起点带进函数体的第一块。第一块的大小按带过来的起点计算。签名本身超过 `desired` 时允许这一块超长，不拆签名。`tree_sitter::Node` 实现了 `PartialEq`，可以直接比较。

跑 `cargo test -p semble-core chunk::` 确认新测试通过、旧测试不回退。

### 2. 定义记录所在行

文件：`index/snapshot.rs`、`index/lexical.rs`、`index/typed_definitions.rs`、`config.rs`

- `IndexedDefinition` 增加 `pub line: usize`，含义是定义名所在的源码行（从 1 开始）。
- `extract_definitions`：`line = chunk.start_line + chunk.content[..name.start()].matches('\n').count()`，`name` 是捕获组 1。用名字的位置，不用整个匹配的起点，因为正则开头的 `^\s*` 会吞掉前面的空行。
- `typed_definitions.rs`：两处 `IndexedDefinition` 都用名字节点的 `start_position().row + 1`（枚举成员用 `enum_member` 里拿到的名字节点；如果函数签名不便取节点，就改成同时返回行号）。
- `lexical.rs` 的私有 `Definition` 结构同样带 `line`，`from_files` 里从 `IndexedDefinition` 拷过来。
- `IndexSnapshot::validate`：定义行不在所属块 `start_line..=end_line` 内时返回 `Error::CorruptIndex`，消息写明文件和符号，例如 `"definition {symbol} line {line} is outside its chunk in {path}"`。先在 `snapshot.rs` 的测试里写 `a_definition_outside_its_chunk_is_rejected`，再加校验。
- `INDEX_FORMAT_VERSION` 改为 13。块边界和定义结构都变了，旧索引必须重建。不做迁移，不读旧格式。
- 修好所有构造 `IndexedDefinition` 的测试代码（`store.rs`、`lexical.rs` 测试里用的是 `extract_definitions` 和 `Vec::new()`，按编译器提示补）。

### 3. 命中定义时，片段从定义行开始

文件：`index/lexical.rs`、`search/engine.rs`

先写测试（`engine.rs` 的 `tests` 模块，使用 `KeywordEmbedder` 和 `SearchRequest::new(name, root)`，即产品默认的 10 行片段；需要时调小 `config.desired_chunk_bytes`）：

- `an_exact_name_search_shows_the_definition_line`：Python 文件里一个短函数后接一个被拆开的大函数（多行签名）。按大函数名搜索，断言 `results[0].start_line` 等于定义行，`results[0].content` 的第一行以 `def large(` 开头。
- `an_exact_name_search_shows_a_later_definition_in_a_shared_chunk`：一个文件里四个三行的小函数，全部落在同一块。按第四个函数名搜索，断言 `start_line` 是它的定义行，`content` 第一行是它的 `def`。
- 这两个测试也要在“落盘后重新加载的引擎”上成立（参照 `disk_loaded_indexes_read_result_snippets_from_source` 的写法，`chunk.content` 为空时片段从源文件读取）。

实现：

- `rank_symbol`、`exact_symbol` 的返回值带上定义行：改成 `Vec<SymbolHit>`（`chunk`、`score`、`line`），或三元组。同一块里有多个同名定义时取最小行。
- `InferredSymbol` 增加 `line`。
- `engine.search`：精确符号路径（`exact_symbol`）和推断符号中排在前面的 `leading` 定义，把 `chunk → line` 记进一个 `HashMap<usize, usize>`。`declarations` 路径已经按声明的行范围返回，不用改。自然语言排序得到的其他块不加锚点。
- `response(...)` 增加参数 `anchors: &HashMap<usize, usize>`（`find_related` 传空表）。某个结果有锚点、且锚点在块的行范围内时：`start_line` 为锚点行，`end_line` 仍是块的结束行；片段从锚点行开始取 `max_snippet_lines` 行。`chunk.content` 非空时先跳过 `锚点行 - chunk.start_line` 行；为空时调用 `source_span(path, 锚点行, chunk.end_line, lines)`。锚点不在块内时按原样返回，不报错。

### 4. 评测按模型实际看到的文本判分

文件：`support/benchmarks/semble/examples/repoqa-query.rs`、`support/benchmarks/repoqa/benchmark.py`、`test_benchmark.py`

- `repoqa-query.rs`：删掉 `request.max_snippet_lines = Some(0);`，使用产品默认值。保留 `hits` 输出不变（其他脚本在用），另输出 `"shown"`：每个结果 `[path, start_line, start_line + 显示行数 - 1]`。显示行数按产品的做法计算：内容先截到 2,000 个字符（与 `apps/semantic-mcp/src/search.rs` 的 `MAX_SNIPPET_CHARS` 相同，在这里写一个同值常量并注明出处），再数行。没有内容时行数为 0。
- `benchmark.py`：把 `next((i for i, hit in enumerate(hits, 1) if covers(hit, expected)), None)` 提成函数 `first_covering(hits, expected)`。`retrieval()` 里新增 `shown_rank = first_covering(reply['shown'], expected) if 'shown' in reply else None`（上游 Python 引擎不输出 `shown`）。`summarize()` 对有 `shown_rank` 字段的引擎增加 `shown_at_5`、`shown_at_10`。
- `test_benchmark.py` 先写 `test_a_covering_hit_is_shown_only_when_its_visible_lines_include_the_definition`：`hits` 覆盖定义行而 `shown` 不覆盖时，`rank` 有值、`shown_rank` 为 `None`。
